# Ladder Bidding documentation foundation

## Goal

Create a low-friction workspace for developing a new board game idea under the
working name “Ladder Bidding,” using the useful document structure from
`../bg-stargate-inc` without importing that game's rules or application code.

## Constraints

- Treat “ladder” and “bidding” as prompts, not settled mechanics.
- Keep the archive readable from the filesystem with no build step.
- Make open questions, hypotheses, and decisions visually distinct.
- Keep space for printable assets, diagrams, sketches, references, and retired
  designs.

## Steps

1. Establish repository conventions, entry points, and archive/asset folders.
2. Add linked rules, design, component, playtesting, and version documents with
   starter prompts and a responsive visual system.
3. Add and run a local documentation validator, then inspect representative
   desktop and mobile renders.
4. Review the implementation and resolve all high- and medium-severity findings.

## Done when

- Every page is reachable from the docs index or a linked workflow.
- Every local link resolves.
- Every HTML page has a title, one `h1`, and a viewport declaration.
- The docs remain usable at narrow viewport widths and when printed.
- No unmarked game mechanic is presented as decided.
