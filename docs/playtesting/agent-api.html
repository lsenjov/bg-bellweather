Playtest agent API

The authenticated local contract shared by browser players and automated seats.

Index/Playtest agent API

Run the application locally at http://127.0.0.1:4317. Every seat receives an opaque bearer token. A command’s acting seat and timestamp always come from the server. Do not supply either field: strict command validation rejects unknown fields.

Implemented

Start and connect

npm install
npm run build
npm start

# Development, with source packages and server reload
npm run dev

Create a table with POST /api/v1/games, or join one with POST /api/v1/games/join. Both responses contain a session with gameId, seatId or spectatorId, and accessToken. Keep the token private and send it as Authorization: Bearer ….

HTTP routes

MethodRoutePurpose
GET/api/v1/healthServer and ruleset health.
POST/api/v1/gamesCreate a lobby and host seat.
POST/api/v1/games/joinJoin by invite code as a player or spectator.
GET/api/v1/games/:id/stateGet the authenticated public plus seat-private projection.
POST/api/v1/games/:id/commandsSubmit an idempotent lobby or game command.
GET/api/v1/games/:id/replayGet canonical full-information events after completion.
WS/api/v1/games/:id/eventsResume from a sequence and receive redacted live events.

Command envelope

{
  "gameId": "uuid",
  "idempotencyKey": "agent-turn-0042",
  "expectedVersion": 17,
  "command": {
    "type": "game_action",
    "action": { "type": "set_counterbid_ready", "ready": true }
  }
}

expectedVersion is optional. Supplying it rejects decisions made from stale state. Reusing the same idempotency key with the same request returns the first acceptance; reusing it for different content is an error.

Lobby commands are {"type":"set_lobby_ready","ready":true} and host-only {"type":"start_game"}. Public chat uses {"type":"post_chat","message":"…"}. A gift uses type give_resources, recipientSeatId, nonnegative integer clout, bluff, and points, plus an operations object containing nonnegative integer organise, rally, smear, and court counts; at least one transferred value must be positive. Player game actions are submit_openings, set_counterbid, set_counterbid_ready, resolve_pecking_swap, resolve_party_operation, and set_election_ready. Election draws and timer expiry are server-only.

ActionRequired payload
submit_openingsopenings[], each containing firmId, partyId, integer clout, integer bluff, and all four integer operation counts.
set_counterbidslotIndex from 0–3 and bid, either null to withdraw or an object containing contestId, firmId, clout, bluff, and operation counts.
set_counterbid_readyBoolean ready.
resolve_pecking_swapdecisionId from private state and adjacentIndex from the projected legal indexes.
resolve_party_operationdecisionId, operation, and a matching choice. Organise uses destination and optional source district IDs; Rally uses a district; Smear uses a district and rival party; Court uses a target party. To claim a bonus, wrap the baseline under choice with claimBonus: true; Murmuration also supplies repeatChoice.
set_election_readyBoolean ready, after phase.resultsRecorded becomes true.
 
{
  "type": "resolve_party_operation",
  "decisionId": "decision-19",
  "operation": "smear",
  "choice": {
    "choice": {
      "operation": "smear",
      "districtId": "harbormouth",
      "rivalParty": "old-shell"
    },
    "claimBonus": true
  }
}

An accepted command returns gameId, the same idempotencyKey, and the new version/latestSequence. Illegal choices return a structured protocol error; refetch state after a version conflict or another seat’s action.

Visibility

Public state includes the phase, public points, map Support, overtures, Pecking Order, contest targets, readiness, chat, retained round reveals, and Election results. A seat projection additionally includes only that seat’s reserve, scoring card, covered bid contents, cover slots, and pending decision. Spectators receive public state only. Live canonical events never disclose hidden engine payloads or gift contents.

After the game ends, every authenticated participant may fetch the complete event history and canonical final state. Random setup and Election draws are recorded, so replay never rerolls.

WebSocket resume

{
  "type": "authenticate",
  "gameId": "uuid",
  "accessToken": "opaque token",
  "afterSequence": 17
}

Omit afterSequence to receive a current snapshot. Include it to receive later projected events. Refetch the state after an event when the agent needs the newest legal-action context.

The reusable TypeScript client is in packages/testkit; a runnable conservative agent is in examples/playtest-agent.ts.
