Playtest agent API

The authenticated local contract shared by browser players and automated seats.

Index/Playtest agent API

Run the application locally at http://127.0.0.1:4317. Every seat receives an opaque bearer token. A command’s acting seat and timestamp come from the server; strict validation rejects unknown fields.

Ruleset 26

Start and connect

npm install
npm run build
npm start

# Development, with source packages and server reload
npm run dev

Create a table with POST /api/v1/games, or join one with POST /api/v1/games/join. Both responses include a session with gameId, a participant ID, and accessToken. Send the token as Authorization: Bearer ….

{
  "displayName": "Ada",
  "controller": "agent",
  "configuration": { "allowSpectators": true }
}

The host may start after two to six players have joined. Starting freezes the seat list and assigns the low-player doubled setup automatically when required. There is no auction timer configuration.

Command envelope

{
  "gameId": "uuid",
  "idempotencyKey": "agent-turn-0042",
  "expectedVersion": 17,
  "command": {
    "type": "game_action",
    "action": { "type": "pass" }
  }
}

expectedVersion is optional. Supplying it rejects a decision based on stale gameplay state. Reusing an idempotency key with identical content returns the first acceptance; different content is an error. Lobby commands are set_lobby_ready and host-only start_game. Public chat uses post_chat.

ActionRequired payload
open_partyfirmId and an unopened partyId. Submit only while the projected opening cursor names the seat.
operatepartyId and one play. An ordinary play contains cardType: "operation", a matching operation, and choice. A Bonus play contains cardType: "bonus", a held bonusCardId, and choice. The card resolves immediately; a second or third play must use the same party, and the third ends the action automatically.
finish_operateNo additional fields. Submit after the first or second resolved card to finish the sequence and pass play clockwise.
collectpartyId for any open party and bonusCardId when any Bonus is available there. The engine spends one Collection counter even when the pile is empty and no Bonus card is available.
closepartyId for an open party whose Firm marker belongs to the acting player and bonusCardId when any Bonus is available there. Illegal on that player’s first Lobby turn of the year.
choose_closure_bonuspartyId for the current automatic-Closure choice and a required bonusCardId. Choose one available card. Only the owner of the Firm marker that was on that party may submit it.
passNo additional fields. Legal only after every Firm marker controlled by the acting player has returned; it does not end the year.
set_election_readyBoolean ready, after phaseData.resultsRecorded is true.

Ruleset 26 uses one private scoringCardId per human. Public state includes pendingPolicies keyed by region, enactedPolicyIds, discardedPolicyIds, and policyDeckCount. The undealt deck is hidden. Parties vote by their public issue priority orders.

Operation choices: Organise uses destinationDistrictId, optional sourceDistrictId, positive integer count (default 1; at most 2 with Carpooling, or 54 for Canal Network), and optional swapPartyIds for Political Exchange. Rally uses districtId and optional sourceDistrictId for extended placement. Smear uses districtId, rivalParty, and optional displacementDistrictId. Bonuses may additionally need bonusDistrictId or bonusDistrictIds.

Each Operation may include freshStartDistrictId, chainSourceDistrictId, and followUpOrder. The order must list each triggered extra exactly once: numeric effect IDs 6, 17, 28, 29 and the string "bonus". Omission uses that default order. The firm can freely order all extras together. Law extras must resolve if possible and otherwise skip; required Bonus extras must succeed. Dig In skips a full source; Midnight Leak skips if no matching rival is available. Displacement preserves the Smear Bonus’s original district and rival. Laws apply once per card, without loops.

Unbound choices use an effect discriminant:

  • every_bee_counts: no extra fields.
  • common_cause: districtId, partnerPartyId; partner shares Honeycomb’s vote on the region’s pending policy and is present. Requires two free spots.
  • whisper_network: sourceDistrictId, destinationDistrictId, rivalPartyId.
  • joint_campaign: regionId, boolean forPolicy, destinationDistrictId, and one to three moves with sourceDistrictId and partyId.
  • institutional_memory: regionId, boolean forPolicy, and one to three placements with a unique partyId plus a destinationDistrictId. Include all three parties on that side while space allows; choose which when room is scarce.
  • shell_firm: targetPartyId.
  • mass_transit: ordered districtIds and one supportPartyIds entry per source.
  • empty_every_nest: equally sized sourceDistrictIds and destinationDistrictIds, the maximum feasible number of different qualifying sources and different free destinations where the acting party was absent.
  • midnight_session: targetPartyId, firmId.

Refetch after each accepted card. The same resolver used by the app validates choices against the current policies and board.

An illegal choice returns illegal_action without consuming a turn or card. Refetch state after a version conflict or another seat’s action.

Phase and visibility

publicGame.phase is opening, lobby, closure, election, or complete; phaseData carries the phase cursor. During Openings, turnSeatIds contains ABBA, ABCCBA, or the single clockwise orbit and may repeat a seat. During the Lobby, activeSeatId identifies the only acting seat. A non-null inProgressOperate gives the locked partyId and resolved ordinary and total card counts; the active seat must either continue that Operate action or finish it. During Closure, the phase cursor identifies each current Firm owner’s pending required Bonus-card choice.

Public state includes year, Election number, Early Bird, combined hand and New Year counts, party status and piles, home Bonus cards, Support, policies, Lobby actions, resolved Operations, year and Election history, and chat. Exact opponent hands and New Year areas remain hidden. Seat-private state adds exact inventories, held and New Year Bonus IDs, and scoringCardId. That card remains hidden from others until final Election results.

Election records contain policyVotes with regionId, policyId, forVotes, againstVotes and passed. Final-only scoringCards reveal seatId and scoringCardId. Final scores include policyScore, policyScores (policy ID, gain, loss, net), finalCardCount, finalCardRankBonus, pointsChange and resultingPoints. Earlier Elections have no scores. Earlier ruleset saves are unsupported; start a new table. Collect, Close and automatic Closure reject a missing Bonus selection when cards are available, without changing state.

After the game ends, every authenticated participant may fetch the complete event history and canonical final state. If observer admission was enabled, a new observer may still join by invitation code to obtain replay access; this adds no event to the completed history. Random setup and Election draws are recorded, so replay never rerolls.

WebSocket resume

{
  "type": "authenticate",
  "gameId": "uuid",
  "accessToken": "opaque token",
  "afterSequence": 17
}

Omit afterSequence to receive a current snapshot. Include it to receive later projected events. Refetch state after an event when the agent needs current legality.

The reusable TypeScript client is in packages/testkit; a conservative runnable agent is in examples/playtest-agent.ts. BELLWETHER_PLAYERS sets that agent’s host-only automatic-start target from two to six and defaults to two.
