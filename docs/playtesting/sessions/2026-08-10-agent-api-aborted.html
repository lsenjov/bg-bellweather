Aborted four-agent API playtest

Setup and one partial opening pass exposed an agent-session persistence failure.

Index/Playtesting/Aborted agent API playtest

Session

Date10 August 2026
Rules version11
PlayersFour API-controlled agents: Marigold, Kestrel, Juniper, and Sable; one human observer
DurationAborted during the first opening pass of Campaign Round 1
FacilitatorCodex
Main questionCan four independent agents complete the first Election through the authenticated game API?
ExpectationIf this works, each agent will preserve its private session across orchestration turns, make agenda-informed choices, and advance the timerless game through unanimous readiness.

Prototype changes

None. The counterbid timer was disabled and spectators were admitted through standard lobby configuration.

Observed sequence

  1. All four agents joined, marked themselves ready, and exposed no private bearer tokens to the facilitator or observer.
  2. The host started successfully. The API clearly projected the first opening order as Kestrel, Juniper, Sable, then Marigold.
  3. Kestrel opened Riverworks with 1 Leverage, 1 Rally, and 1 Smear to pursue Riverworks in Harbormouth on SC-04.
  4. Juniper opened Honeycomb with 2 Leverage, 1 Organise, and 1 Rally to pursue Honeycomb in High Pastures on SC-06.
  5. Sable could not act because its bearer token had been retained only in transient tool memory. The join transcript contained only intentionally sanitized fields, and the game API has no token-recovery or seat-reconnection route.
  6. The session was abandoned rather than reading server internals or controlling Sable through another player.

Election Day record

No Election occurred.

Agent interpretations

  • The public phase cursor and private/public projection boundary made turn ownership and legal waiting unambiguous.
  • The seat projection identifies an agenda by card ID only. An agent must consult the repository's card reference to make an agenda-informed choice; the API projection alone does not provide the scoring conditions.
  • Opening composition communicates commitment through total visible card count while leaving operation families concealed, which supported divergent early strategies.

Operational failure

A multi-turn agent must persist the complete participant session, including its bearer token, outside transient tool-call memory immediately after creating or joining a game. A permission-restricted, agent-specific temporary file is sufficient for a local playtest. Sanitized reporting should happen only after persistence succeeds.

Because active games reject new player joins and the API deliberately offers no credential recovery, losing one seat token permanently stalls any phase requiring that seat. This is an orchestration constraint rather than evidence about the game rules.

Result against expectation

Inconclusive for game behavior and contradicted for agent orchestration. The two completed openings showed agenda-informed play, but the session could not reach counterbidding or Election Day.

One next test

Repeat the same four-agent, timerless test after requiring every agent to persist and verify its session before the host starts. Stop after the first Election and record both game outcomes and API friction separately.
