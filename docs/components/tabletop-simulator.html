The digital export uses the current component artwork and rules. Cards are cropped individually; policies have matching unique enacted backs, and the other decks are grouped by their shared back; physical print-sheet margins, mirrored duplex placement and agent clip strips are omitted.

Build and validate

Run from the repository root. The exporter needs Node, Playwright with Chromium, and Python with Pillow. It uses the same browser installation as the print checks.

npm run tts:export
npm run tts:check
python scripts/test-publish-tts-assets.py
python scripts/test-generate-tts-loader.py

Generated files are in assets/tts/. The current manifest.json and import-bellwether.lua are committed so another machine can import the published assets without running the exporter. PNG files remain untracked and are hosted in S3. manifest.json records image URLs, hashes, deck settings, card order and piece quantities. Repeated pieces reuse a single image per design; the manifest records how many copies to create. Images have content hashes in their filenames so future artwork exports can coexist with saved games.

The export contains all 151 cards in sixteen decks: common cards; six party suits; six firm suits; Hecate rewards; policies; and private priorities. It also includes the twelve opening markers, agent faces, reversible Gallery portraits, firm tokens, public markers, boards, twelve player folios, forty-eight private reminders and reference images. The printable suite remains available separately.

Publish to S3

Destination: s3://lsenjov-boardgame-bellwether/tabletop-simulator/, region ap-southeast-2. The default public image URL begins https://lsenjov-boardgame-bellwether.s3.ap-southeast-2.amazonaws.com/tabletop-simulator/. The AWS console bucket page is an administration page, not an image URL.

python scripts/publish-tts-assets.py
python scripts/publish-tts-assets.py --upload

The first command validates files and previews the upload without using AWS credentials. The second uses your configured AWS CLI identity, uploads only files listed in the manifest, and checks that each resulting image URL is accessible without authentication. It does not delete old assets or change bucket policies or ACLs.

The supplied bucket now grants public read access only to tabletop-simulator/*, as approved. Published assets were last verified without authentication on 2026-10-15. Regenerating local exports does not publish updated artwork; upload and verify the current manifest before using its new URLs. This policy grants no listing or write access.

Players need stable public HTTPS access to the images. If the bucket remains private, use your public delivery service, such as CloudFront. Regenerate and publish using the same delivery prefix in both commands:

npm run tts:export -- --base-url https://YOUR-PUBLIC-HOST/tabletop-simulator/
python scripts/publish-tts-assets.py --base-url https://YOUR-PUBLIC-HOST/tabletop-simulator/ --upload

Configuring that delivery service is separate from this export. An upload can succeed while public verification fails; in that case the images are stored but are not ready for other players. Do not use expiring signed URLs in saved games.

Import the component set

python scripts/generate-tts-loader.py

This writes assets/tts/import-bellwether.lua. After publishing the images, start an empty Tabletop Simulator table, paste the script into the Global scripting editor, and save it. Open the console and run lua Global.call("spawnBellwether"). The script imports the manifest's decks and pieces into a staging layout. Allow roughly 50 × 80 Tabletop Simulator units of clear staging space, plus margin for the pieces. Arrange the components, then save the game. Their sizes are set automatically after their assets finish loading. It does not run automatically on load. Run it only once on an empty table; saving/reloading the script resets its duplicate-import guard.

The importer has local generation and Lua syntax checks; its appearance and physics still need an in-game check. Manual import is also available below.

Physical scale and existing tables

The importer uses one world unit per 25.4 mm as a shared scale for all components. It measures each loaded object's rotation-normalized bounds before setting its size; image resolution and native model scale do not determine the finished dimensions. Flat components keep their thickness; standees scale uniformly to 25.4 mm across.

For an existing imported table, replace the Global script with the updated import-bellwether.lua, save it, then run:

lua Global.call("resizeBellwether")

This resizes matching objects already on the table, including the board using its original image URL. It does not spawn copies or change positions, rotations or lock states. Objects are matched by their known asset URLs; unrelated components are untouched. Objects stored inside bags are not exposed to this pass. Run it again after taking those out. Check the layout after resizing and save the table.

For a new table, spawnBellwether applies sizing automatically. The measurement uses the TTS normalized-bounds API. Local tests cover the scaling calculation and asset-loading timing; actual in-game appearance still needs checking.

Show enacted policy backs on an existing table

If an enacted back appears during a flip and then changes to the generic hidden image, the policy object still has Hide Face Down enabled. Update Global with the regenerated assets/tts/import-bellwether.lua, use Save & Play, then run:

lua Global.call("showBellwetherPolicyBacks")

This disables face-down concealment for current policy decks and loose policy cards already on the table, matched by their exact face image URL. It does not spawn replacement components or alter other decks. The script also applies the setting as policy objects finish spawning, including cards drawn from decks or bags, the last card left when a deck collapses, and newly stacked policy decks.

For an immediate manual check, right-click a policy card or deck, open Toggles, and turn Hide Face Down off. Each loose card has its own setting; changing only the deck is insufficient for cards already drawn. The loader automates this setting for future objects. Unique Backs stays enabled and Back is Hidden stays disabled, so genuine hand/hidden-zone concealment still uses the generic hidden image. See the official face-down concealment API.

New imports apply this automatically. No artwork export or upload is needed. Local Lua tests cover the setting, asset readiness and object lifecycle; confirm automatic drawing, restacking and hidden-zone appearance in Tabletop Simulator.

Import components manually

For each manifest deck, create a Custom Deck using face.url and back.url. Set Width and Height to the manifest grid dimensions and Number to its card count. Follow uniqueBack and backIsHidden in the manifest. For policies, enable Unique Backs and disable Back is Hidden: both images are matching atlases, with each proposal and enacted face at the same index. The final cell provides a generic hidden image. Also turn Hide Face Down off for policy cards/decks using the loader or Toggles menu, so the enacted back remains visible on the table after flipping. For all other decks, enable Back is Hidden and leave Unique Backs disabled; their final face cell matches the shared back. These images use normal row order, not physical duplex order. See the official Custom Deck guide.

Use Custom Board for the map and party boards, Custom Figurine for standees, and Custom Tile for flat pieces and references. Gallery portraits have an awake image.url and asleep imageSecondary.url; set both tile faces so flipping changes their state. Respect each object's manifest count. The custom-object API reference lists the corresponding image fields.

Use native coloured pieces for each party's unlimited Support supply. Give each player two Collection cubes, or four at two or three players. Use player hand zones for held cards and private zones for priorities and private reminders. Keep New Year cards concealed while their total count remains visible. Follow the rulebook for setup; importing artwork does not deal cards, place Support or automate firm powers.

Local checks verify asset inventories, image sizes, hashes, atlas geometry and hidden backs. A Tabletop Simulator session is still needed to check physical scale, readability, flipping and privacy before the first playtest.
